# Locked SN71 collection

Miners enroll OpenRouter and Deepline funding keys for operator-run sales agents. The initial harness is the reviewed source in [sales-agent PR 7](https://github.com/leadpoet/leadpoet-sales-agent/pull/7). The host freezes the source revision, scenario pack, generator schedule, rubric, tags, judge versions and routes. The assigned generator handles every model step, including Tyche child sessions. Fresh rounds of agent competition retire at the economic cutover.

## Enrollment

`leadpoet collection-terms` displays the mode, terms and digest. Provide the OpenRouter runtime and management credentials and the Deepline workspace credential through the existing miner CLI environment inputs. Sign `leadpoet collection-register --mode pilot --daily-cap-usd 10 --accept-terms <digest>` with the miner wallet; the example cap is per provider over a rolling 24 hours. The management credential is used only during key validation. The owner can inspect `collection-statement` and use `collection-revoke` with the registration ID. Pilot and live enrollment require distinct signed consent. A pilot incurs real provider charges and pays no emission reward.

The six slots in each comparison pack run Kimi K3.1 Pro, DeepSeek V4 Pro-0813, Inkling 2 Small, Tencent Hy4, GLM-5.3, and DeepSeek V4.1 Flash-1017, respectively, on the same scenario. Each subsequent complete group advances to a fresh scenario. A provider receipt records known spend even when the run fails. Unknown bills retain their reservation. The worker cannot issue the same paid request identifier twice. Both billed generator and tool costs count towards the miner-funded measurement. Private verifier calls use an owner-controlled credential and count against the job budget.

## Running one batch

Use an approved operator environment on the gateway. Source revisions are in `lab_arena/collection_workflow.py`. The public champion and authorized private Poet9B Git checkouts must contain those exact commit objects. The worker materializes the source trees from Git. The private checkout supplies guarded scenario generation, reference answers and deterministic graders.

1. Create a private batch JSON with `name`, `mode`, `seed`, a list of distinct `scenario_ids`, an exact provider tag for each of the six generators and two judges in `routes`, and each generator's `budgets_microusd`. The maximum batch liability is bounded by the sum of its scheduled job caps. The worker hashes these settings into the batch ID. Synthetic IDs include C26-s2027, K02-s2027, B1-s2027, E4-s2027 and P5-s2027. Guarded builders reject held-out seeds, products and tool formats. All synthetic worlds operate on simulated files, people, inboxes and CRM records.
2. Store the private rubric and examples outside Git. Use the format in the [judge contract](judge-output-spec.md). Supply `control_slots`, `drift_slots` and `control_artifacts` alongside a private case pack for a release pilot. Empty maps allow a preliminary reference batch. See the contract for freezing independently labeled planted cases and 30 previously recorded drift cases. A release pilot requires 100 judged ordinary runs spanning the six models, both judges on the pilot, and 50 actual blind human marks.
3. Run `python -m scripts.run_locked_collection --preflight --batch BATCH --prompt PROMPT --control-pack CONTROLS --champion-repo AGENT --poet-repo POET`. This validates and builds the private inputs offline. Separately test actual routes on synthetic content under the approved retention, training-use and price policies before opening funding to miners. Catalog presence is insufficient evidence of an available route.
4. In the approved gateway environment with `LAB_ARENA_COLLECTION_MODE=pilot`, run the same command without `--preflight` and with `--max-jobs 1` to execute one available funded job. Later invocations use the durable batch/slot record. A miner gets at most one new assignment per UTC day per mode. Confirm progress from persisted artifacts, statements and receipts. Keep the reviewer private key and private judge inputs off miner accounts.
5. For real web research, use a validated private index from `scripts.prepare_collection_research_index`, bind its digest in `research_index_sha256`, and pass `--research-case-index INDEX --research-stdio` on the gateway. Connect its binary streams to `python -m scripts.collection_research_worker` on the validator using `python -m scripts.collection_relay --worker-commands COMMANDS` on the authorized operator machine. COMMANDS is private JSON with gateway and validator command argument lists for their existing authenticated SSH/SSM aliases. Use the normal host release environment, exact scorer image cache, pinned dependency tree and champion checkout. A research process runs in gVisor with the ordinary broker and web sockets. A case with missing validation evidence stays out of training until it has sufficient evidence.
6. Publish the registered review bundle via `python -m scripts.collection_batch bundle`. Use `python -m scripts.collection_review sample`, obtain blind human marks, and run `sign` on the reviewer's machine. The operator's `verify` and `collection_batch export` commands bind human marks to the evidence and deployment-pinned reviewer key. Exports contain only original open-generator messages. Select decisions only, reasoning included, or reasoning on designated hard steps. Neither synthetic control packets nor closed-model judge outputs enter training. Quality and funding are tracked separately.

## Activation and settlement

Apply migrations 720–724 in numeric order through the [reviewed RDS migration channel](arena-rds-migrations.md). Deploy all required validator, signer and gateway revisions through the [paired release controller](arena_paired_restart.md). Confirm native routing and data readback before opening paid collection. The existing configuration helper supports a scoped `--collection-mode pilot` check/apply. Prepare each approved live batch within one task family so its model prices and caps come from one measured pilot class.

Run `python -m scripts.collection_batch prices` on the verified, signed pilot evidence. Use the resulting operator-authorized cutover under the [validator weights procedure](arena_normal_validator_weights.md). Reserve the next full epoch only after prior live rounds, promotions and awards finish. The subnet then quotes each verified completed job 125% of measured pilot cost for that class and model. Payout weights are proportional to those fixed quotes. An epoch with insufficient emissions scales every quote by the same factor. Surplus goes to burn. Each job contributes once, with no carry-forward.

The validator can verify a newly discovered company using exact, passive, same-run source fetches when the source URL, company identity, dated signal and quoted facts all match. Its evidence packet identifies these observations separately from previously verified Arena results. Incomplete research and unsupported context remain visible for review. A checkpoint alone cannot earn the fixed fee: the worker must also prove Tyche finalized the run.

Use `scripts.collection_relay` for one research job per invocation. For unattended operation run the bounded command under the operator's service supervisor while the approved pack is active; the next invocation reads the next durable slot. Empty funding queues produce an idle result. Never forward a personal SSH agent or an OpenRouter/Deepline key into the sandbox.

The optional private manifest field `thresholds` contains `accept_sum`, `salvage_min_steps` and `agreement_percent`. Defaults of 10/15, three steps and 85% are provisional. A preliminary calibration batch can establish 30 real reference outputs before that sample is frozen and rejudged as drift controls.
